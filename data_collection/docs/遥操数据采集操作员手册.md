# GELLO + Sharpa 多模态遥操数据采集操作员手册

本文面向现场遥操操作员，用于完成“双臂 + 双手 + 三相机 + 双手触觉”的连续 episode
采集。本文只描述日常操作，不用于安装环境、修改参数或排查底层代码。

标准工作流使用三个终端：

1. 双臂 GELLO 遥操；
2. MANUS/Sharpa 双手遥操和触觉发布；
3. 双臂、双手、三相机及 20 路触觉统一录制。

## 1. 安全原则

- 操作前清空左右机械臂工作空间，急停必须在操作员随手可及的位置。
- 启动机械臂跟随前，双手扶稳 GELLO，禁止在 GELLO 正在移动时点击 `Start arm`。
- 每次开机先单臂、小幅度验证方向，再进行双臂动作。
- Operator GUI 中的 `Start arm` 才是机械臂跟随使能。
- `Hold arm` 只让机械臂保持当前位置，不等于停用控制，也不代替急停。
- 软件异常时先点击 `DISENGAGE ALL`；存在碰撞危险或软件来不及响应时使用硬件急停。
- 不要同时启动两套双臂遥操、两套 Sharpa 手部程序或两个录制器。
- 不要在双臂遥操期间运行 `manus_sharpa_record/record.py`，它会尝试直接占用 FR3 FCI。

## 2. 每次采集前检查

### 2.1 机器人和工作区

- 两台 FR3 已上电，在 Panda Desk 中解锁并启用 FCI。
- 左右机械臂周围无人员、线缆、工具和其他障碍物。
- 硬件急停可用且位置明确。
- 左右 GELLO、两只 Sharpa 手和 MANUS 手套连接正常。
- 两只 GELLO 在点击 `Start arm` 前保持静止。

### 2.2 相机

- 头部网络相机、左腕相机和右腕相机均已供电并接好。
- OrbbecViewer 已完全关闭，否则录制程序可能无法打开相机。
- 头部相机断电后，其网络地址可能发生变化。当前项目期望：

```text
头部相机序列号：CP4N651006F
头部相机 IP：192.168.1.123
头部相机端口：8090
电脑相机网口：192.168.1.53/24
```

如果终端反复显示找不到 `cam0` 或头部相机无帧，不要直接修改项目参数。先停止采集，
使用 OrbbecViewer 确认相机实际地址；需要改回地址时交由设备管理员处理。

### 2.3 踏板和 GUI

- 两块 USB 踏板都已连接。
- Operator GUI 窗口必须获得键盘焦点，踏板才会响应。
- 机械臂 Hold 踏板发送 `A`（左臂）和 `C`（右臂）。
- 数据采集踏板发送 `L`（开始/停止）和 `Space`（中间标记）。

## 3. 启动顺序

所有命令都在以下目录执行：

```bash
cd /home/user/gello_upper_body_teleop
```

### 3.1 终端 1：启动双臂遥操和 Operator GUI

```bash
./ops/run/run_gello_arms_only.sh
```

等待预检通过、Docker 服务启动，并出现 Operator GUI。确认 GUI 顶部连接状态为
`CONNECTED`。

程序启动时机械臂默认未跟随。首次运动按以下顺序进行：

1. 急停放在手边，确认工作空间清空；
2. 扶稳两只 GELLO；
3. 只点击一侧的 `Start arm`；
4. 用很小的已知动作确认关节方向和响应正常；
5. 停用该侧，再用相同步骤检查另一侧；
6. 两侧均正确后，按任务需要启用双臂。

如果机械臂方向、响应或零位明显异常，立即 `DISENGAGE ALL`，不要继续采集。

### 3.2 终端 2：启动双手和触觉

```bash
./ops/run/run_sharpa_hands_cyclonedds.sh
```

确认终端没有 MANUS、Sharpa、校准目录或 DDS 报错。佩戴手套后分别做一次张开、轻握和
单指轻触，确认左右手对应正确、动作方向正常、无持续异常抖动。

本工作流的 Sharpa 双手由终端 2 独立运行，不使用机械臂 Hold 踏板控制。Operator GUI
中的机械臂 `Start arm`/`Hold arm` 也不控制这套 Sharpa 进程。

### 3.3 终端 3：启动触觉版采集器和三相机

只有在双臂、双手均确认正常后，才运行：

```bash
./ops/run/start_sharpa_arm_recording_with_tactile.sh --with-cameras
```

等待相机、机械臂、双手和 20 路触觉检查完成。只有终端明确显示：

```text
READY: 采集器已准备好，可以开始录制。
```

且 Operator GUI 数据采集区域显示 `READY`，才可以开始 episode。

不要同时运行普通版：

```bash
./ops/run/start_sharpa_arm_recording.sh --with-cameras
```

普通版和触觉版是两个互斥的终端 3 方案，同时启动会造成端口占用或录制冲突。

## 4. 单条 episode 的标准操作

### 4.1 录制前摆位

1. 确认 GUI 数据采集状态为 `READY`；
2. 确认 Operator GUI 位于前台并获得键盘焦点；
3. 将双臂和任务物体放到起始位置；
4. 无人进入机械臂工作区的短暂停顿，可用 `A`/`C` 分别打开左右臂 Hold；
5. 开始动作前解除所需机械臂的 Hold；
6. 再次确认人员和障碍物均已离开工作空间。

如果人员需要进入机械臂工作区或近距离调整物体，不能只使用 Hold；必须先停用对应机械臂
跟随，必要时使用硬件安全措施，人员退出后再重新使能。

### 4.2 开始录制

使用以下任一方式：

- 踩数据采集踏板的 `L`；
- 点击 GUI 的“开始录制 (L)”。

开始后，GUI 状态应变为红色 `RECORDING`，按钮文字变为“停止并校验 (L)”。若状态未
变化，不要开始任务动作，应先检查 GUI 是否获得焦点以及终端 3 是否仍在运行。

### 4.3 执行任务和中间标记

- 按任务要求完成自然、连续的双臂双手操作。
- 触觉任务应确保需要参与的手指真实发生接触，不要只做空中动作。
- 需要标记一个中间完成点时，踩 `Space` 或点击“中间完成标记 (Space)”。
- `Space` 只写入标记，不会暂停或结束录制。
- 非必要不要重复打点；每次打点后 GUI 会显示累计标记数量。

### 4.4 停止并校验

动作完成后，再踩一次 `L`，或点击“停止并校验 (L)”。此后：

1. GUI 显示 `STOPPING`；
2. rosbag 写入缓存并生成 `metadata.yaml`；
3. 系统自动校验相机、机械臂、双手和触觉数据；
4. 校验完成后弹出“数据质量评价”。

等待该流程完成。不要在单条 episode 结束时按 `Ctrl-C`，否则可能留下未完整收尾的 bag。

### 4.5 选择数据质量

现场建议按以下标准选择：

| 选项 | 使用条件 |
| --- | --- |
| 优等 | 任务完整成功，动作自然，无碰撞、误操作和明显数据告警 |
| 一般 | 任务成功且数据可用，但动作质量或过程存在轻微瑕疵 |
| 报错 | 设备、控制、相机、触觉或校验出现异常 |
| 放弃 | 任务失败、操作员主动中止，或该条数据不应进入后续使用 |

选择完成后，等待采集状态重新回到 `READY`，再开始下一条。评价完成前不能开始下一条。

## 5. 踏板与按钮速查

| 输入 | 功能 | 注意事项 |
| --- | --- | --- |
| 左侧机械臂踏板 `A` | 左臂 Hold 开/关 | 不是 Start，也不是急停 |
| 右侧机械臂踏板 `C` | 右臂 Hold 开/关 | 不是 Start，也不是急停 |
| 数据踏板 `L` | 开始录制；录制中再次踩下则停止并校验 | 必须等待状态变化 |
| 数据踏板 `Space` | 记录中间完成点 | 不会停止录制 |
| GUI `Start arm` | 启用对应机械臂跟随 | 点击前扶稳 GELLO |
| GUI `Hold arm` | 对应机械臂原地保持 | 控制链仍在运行 |
| GUI `DISENGAGE ALL` | 停止所有软件跟随 | 软件异常时优先使用 |
| 硬件急停 | 紧急停止硬件 | 存在碰撞危险时使用 |

踏板是普通 USB 键盘模拟设备。长踩不会重复触发，但 Operator GUI 失去键盘焦点后踏板
不会响应。踩踏板后必须观察 GUI 状态，不能只凭脚感判断命令是否生效。

## 6. 正常现象与异常处理

| 现象 | 判断与处理 |
| --- | --- |
| 终端 3 启动时等待相机数十秒 | 初始化期间可以等待；必须最终进入 `READY` |
| `cam0 ... no frames` 持续出现 | 检查头部相机供电、网线和实际 IP；不要继续录制 |
| `Device with serial number ... not found` | 对照相机序列号和接线，关闭 OrbbecViewer 后重试 |
| `Control port 5590 is already used` | 已有终端 1/Operator 在运行；不要重复启动 |
| `5592 ... already in use` | 已有采集器运行；不要再启动第二个终端 3 |
| `Connection to FCI refused` | 在 Panda Desk 重新确认对应 FR3 已启用 FCI |
| GUI 显示 `DISCONNECTED` | 确认双臂已经停止；仍有风险时按下硬件急停，并联系维护人员 |
| 踩踏板没有反应 | 点击 Operator GUI 让其获得焦点，再观察状态；不要连续乱踩 |
| 校验出现 failure | 本条选择“报错”或“放弃”，保存终端日志并联系维护人员 |
| 只有 transport warning | 不自行判定数据合格；结合任务表现和校验详情选择质量 |
| 机械臂方向或响应异常 | 立即 `DISENGAGE ALL`；有碰撞风险时按硬件急停 |

不要为了绕过报错而修改端口、QoS、频率阈值、CPU 配置、相机序列号或机械臂安全参数。

## 7. 数据位置与结束整场采集

触觉版数据默认保存在：

```text
$TELEOP_DATA_ROOT/bags/gello_sharpa_tactile/episodeN/
```

质量分类记录在：

```text
$TELEOP_DATA_ROOT/数据分类/gello_sharpa_tactile/
```

结束整场采集时：

1. 确认当前没有处于 `RECORDING` 或 `STOPPING` 的 episode；
2. 完成本条质量评价，等待状态回到 `READY`；
3. 点击 `DISENGAGE ALL`，确认双臂不再跟随；
4. 在终端 3 按 `Ctrl-C`，等待采集器和相机正常退出；
5. 停止终端 2 的 Sharpa 双手程序；
6. 最后停止终端 1 的双臂遥操栈；
7. 不要在程序仍写盘时拔移动硬盘或关闭电脑。

首次采集或设备维修后，先录制一条 15 至 20 秒测试数据，确认三路相机、双臂、双手、
20 路触觉、`metadata.yaml` 和 `collection_state.json` 均正常，再开始正式批量采集。

## 8. 操作员不得自行修改的内容

以下内容由设备或开发维护人员管理：

- `docker/.env` 中的端口、ROS domain 和 CPU 集合；
- `config/workcell/current.yaml` 中的机器人 IP 和控制 CPU；
- `config/modes/gello.yaml` 中的串口、方向和关节灵敏度；
- `data_collection/config/cameras.yaml` 中的相机序列号；
- `docker/compose.yaml` 中头部相机 IP/端口；
- 录制 topic、QoS、频率和最大间隔验收阈值。

出现无法恢复的异常时，记录发生时间、正在执行的任务、GUI 状态、三个终端最后一屏日志
和对应 episode 编号，再交给维护人员处理。
